# zerosint Bug-Fix Sweep Implementation Plan

**Goal:** Fix the bugs found in a full read of zerosint on 2026-10-25 without changing what the tool does.

**Architecture:** Each task is one self-contained fix with its own unittest file, so any task can be reviewed or reverted on its own. No new dependencies. Module wrappers keep their current shape: `available()`, `handles()`, `run(seed) -> list[Finding]`.

**Tech Stack:** Python 3.14 (the `.venv` inside the repo), `unittest` + `unittest.mock`, requests, rich, pyvis 0.3.2.

**Spec:** None. This plan comes from a code read plus probes run in Kali WSL on 2026-10-25. Each task says what was observed.

## Global Constraints

- zerosint runs **only inside WSL (kali-linux)**. Run every command there, never on native Windows.
- Test runner: `wsl -d kali-linux -- bash -lc 'cd /path/to/zerosint && .venv/bin/python tests/<file>.py -v'`. pytest is not installed. Don't add it.
- Full suite: `wsl -d kali-linux -- bash -lc 'cd /path/to/zerosint && .venv/bin/python -m unittest discover -s tests -p "test_*.py"'`. Baseline: 47 tests, OK.
- New test files copy the header of `tests/test_xposed_mod.py`: the `sys.path.insert(0, <repo root>)` line, unittest classes, `if __name__ == "__main__": unittest.main(verbosity=2)`.
- No network in tests. Mock `requests.get`, `_exec` and `time.sleep`.
- Do the work on a branch named `bugs-fixes`, never on `main`.
- No new pip dependencies.
- Code, comments and log messages stay in English, matching the codebase.

## Review Focus

1. **Real Kali install layout.** SpiderFoot ships as `/usr/bin/spiderfoot`, a wrapper that runs `sf.py "$@"`. Task 5 must make the module find it (pinned by `test_found_as_kali_spiderfoot_binary`).
2. **Emails on free webmail.** `someone@gmail.com` must not start theHarvester/recon-ng/SpiderFoot scans of gmail.com. An explicit `--domain gmail.com` still must (Task 3).
3. **One breach, several accounts.** Two seed emails both in "Adobe" must give two breach rows, each with its own account (Task 2).
4. **HIBP returning 429 forever.** The scan has to finish, not recurse until a RecursionError (Task 1).
5. **Opening the HTML report offline.** The graph must not point at `lib/bindings/utils.js`, which doesn't exist next to the report (Task 6).

### Task 1: Bounded HIBP retry and URL-safe accounts

**Observed:** `BreachModule.run` calls itself again on every 429, with no limit (`modules/breach_mod.py:88-91`). A non-numeric `Retry-After` header raises ValueError. Neither breach module URL-encodes the account, so `a+b@x.com` gets sent as `a b@x.com`. `check_password_pwned` crashes on any line without a `:`.

**Files:**
- Modify: `modules/breach_mod.py`

- Create: `tests/test_breach_mod.py`
- Modify: `tests/test_xposed_mod.py` (one new test)

**Interfaces:**
- Produces: `BreachModule._get(self, account: str) -> requests.Response | None`. On 429 it retries up to `MAX_RETRIES = 3` times (so at most 4 requests). Wait before retry n (0-based) is the `Retry-After` header in seconds when it parses as an int, otherwise exponential backoff `BACKOFF_BASE * 2**n` with `BACKOFF_BASE = 1`. Every wait is clamped to `[0, MAX_RETRY_WAIT]`, `MAX_RETRY_WAIT = 10`. After the last 429 it logs one `log.error("[breach] HIBP still rate limited for %s after %d retries, skipping", ...)` and returns None.
